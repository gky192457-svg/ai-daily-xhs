# 每日自动化任务的 Prompt 工程

这是驱动整个流水线的 7 步任务 Prompt（实际运行于每日 08:00 的定时任务）。它体现了 AI PM 的核心技能：**把模糊的内容生产流程，拆解为可约束、可验证、可降级的确定性步骤**。

---

## 完整 Prompt

```text
你正在运行一个每天 08:00 自动执行的定时任务，产出并发布一篇「AI 日报」小红书图文笔记。
请严格按以下步骤顺序执行，全程自主完成：

【STEP 0 — 异常速查】
若渲染或发布环节出现任何报错/异常（坐标 TypeError、中文变豆腐块、点击超时、按钮无反应、
取图目录错等），先查阅 docs/TEMPLATE_B.md（模板B规范，含渲染要点）
与 docs/LESSONS.md（踩坑手册），按文档处理，不要盲目重试。

【STEP 1 — 采集过去 24 小时 AI 资讯】
用 WebSearch（中文来源优先）搜集最近 24 小时的真实 AI 资讯，必须覆盖四大主题：
1. AI 行业发展（融资/并购/大厂动向/市场趋势）
2. AI 最新动态（新模型/新工具发布、开源突破、平台更新）
3. AI 产品经理（岗位变化、能力要求、职业趋势）
4. AI 行业薪资（薪资水平、最热岗位、薪酬趋势）
每个主题收集 3–4 条具体资讯，每条含：吸睛短标题、1–2 句详情（事实/数字必须准确）、来源。

【STEP 2 — 整理薪资图表数据】
在「AI 行业薪资」主题下，挑选 4–5 个代表性 AI 岗位，给出年薪代表值（万元/年），
提供 labels 与整数 values。

【STEP 3 — 用亲和幽默的语气重写】
把所有标题/摘要/详情改写成亲和幽默语气（像朋友聊八卦），不得改动事实数字和核心事实；
每个主题加「小编说：」式俏皮导语。

【STEP 4 — 输出结构化 JSON】
写入 <repo_root>/<今天的日期 YYYY-MM-DD>.json，严格使用 samples/2026-10-25.json
的 schema（四主题 key 固定为 ai_industry_dev、ai_latest、ai_product_manager、ai_salary；
含 topics/takeaways/caption/hashtags）。必须包含：
(a) title 字段：小红书笔记标题，≤20 字，必须带当天最炸的一个数字钩子；
(b) 每个主题的 cover_hook 字段（封面钩子）：只写当天该板块最炸的一条具体数字/事件；
    用 \n 精确断成两行，每行一个信息点，不要依赖自动换行；
    每行不超过 13 个汉字或等宽拉丁；语气亲和幽默但数字必须真实准确。
注意：caption 正文里不要出现「每天 8:00 自动整理」或任何暴露自动化工具名的字样。

【STEP 5 — 渲染「模板B · 终端极简」风格图片】
python pipeline/render_template_b.py <repo_root>/<日期>.json --outdir <repo_root>/output_b
生成 6 张 1080×1440 PNG 及 caption.txt。视觉规范见 docs/TEMPLATE_B.md，
禁止改动 render.py 中的视觉参数。核心规范：GitHub Dark 近黑底 #0D1117 + 极淡点阵；
语法高亮四色；等宽 Consolas 跑纯拉丁、Noto Sans SC 跑中文；路径栏/行号/## 标题/
// NOTE: 注释块/$ 命令行；封面四板块卡各配迷你数据图；总结页 CHANGELOG 风。
品牌名固定「零阶产品谱」。

【STEP 6 — 发布到小红书（Playwright 自动化）】
先 Read publish_flow.js（v3 版：取图目录为 output_b/，勿取错成 output/）；
调用 browser_run_code_unsafe，将 code 参数设为该脚本全文。
脚本自动完成：读 JSON → 打开发布页 → 切「上传图文」→ 注入 6 张图 → 填标题/正文 →
选「笔记含AI合成内容」声明 → 点红色发布按钮（坐标 742,955）→ 校验 published=true。
若发布失败（任何原因）：不要无限重试。改为保留产物 + 写草稿说明 + 通知用户。

【STEP 7 — 汇报】
总结：采集多少条资讯、输出图片路径、发布成功还是转为草稿待发布。

硬性约束：图片必须来自渲染管线；所有事实数字保持准确，仅语气幽默；
日常模板固定为模板B，未经用户要求不得切回；本任务须完全自主，
仅在发布失败时回退为通知用户。
```

## Prompt 设计要点拆解

| 手法 | 示例 | 解决的问题 |
| --- | --- | --- |
| **步骤原子化** | 7 个 STEP，每步单一职责 | 任一步失败可定位、可重试，不污染其他步 |
| **约束量化** | 「≤20 字」「每行 ≤13 汉字」「4–5 个岗位」 | 把主观质量标准转为可验证数值 |
| **负面清单** | 「不得改动事实数字」「禁止出现工具名」「不要无限重试」 | 阻断 LLM 常见失效模式 |
| **格式锚定** | 固定 key 名、`\n` 断行规则、schema 引用 | 保证下游渲染器可解析 |
| **降级路径** | 发布失败 → 草稿 + 通知 | 外部动作失败不停摆，有人工兜底 |
| **异常前置** | STEP 0 先查坑位文档再动手 | 避免重复已知错误，减少无效 token 消耗 |
| **内容策略产品化** | cover_hook 的「数字钩子 + 精确断行」 | 把爆款封面规律写成字段约束 |
