# 架构说明

## 1. 总览

```
┌──────────┐   ┌──────────┐   ┌───────────┐   ┌──────────────┐   ┌──────────┐
│ WebSearch│ → │ LLM 改写 │ → │ 数据层 JSON│ → │ 模板渲染引擎 │ → │ Playwright│
│ 资讯采集  │   │ 语气/结构  │   │ (schema)   │   │ Pillow 绘图  │   │ RPA 发布  │
└──────────┘   └──────────┘   └───────────┘   └──────────────┘   └──────────┘
```

## 2. 分层职责

### 数据层（schema 契约）

数据层是全文的「单一事实源」，字段设计即产品决策：

| 字段 | 类型 | 产品意图 |
| --- | --- | --- |
| `date` | string | 内容归档与编号（NO.298 序列） |
| `title` | string ≤20字 | 平台标题限制 + 数字钩子策略 |
| `topics[key].cover_hook` | string | **爆款封面钩子**：当天最炸数字，`\n` 断两行，每行 ≤13 字 |
| `topics[key].summary` | string | 「小编说」导语，幽默语气但零事实改动 |
| `topics[key].items[]` | array | 结构化资讯：headline / detail / source（来源可溯） |
| `topics[key].chart` | object | 薪资页图表数据（labels + values） |
| `takeaways[]` | array | 总结页 5 条要点 |
| `caption` / `hashtags` | string/array | 发布文案，禁用自动化工具名 |

### 视觉层（模板引擎）

渲染引擎只消费 schema，不关心数据来源。两个模板验证了同一抽象：

- **模板A**：`render_template_a.py` —— 赛博夜城风。垂直渐变底 + 三层径向柔光 + 胶片颗粒 + 暗角；四主题实色渐变块（顶亮底深）+ 边缘亮色高光；轻磨砂面板（投影 alpha46/blur7 + 1px 描边）。
- **模板B**：`render_template_b.py` —— 终端极简风。GitHub Dark 近黑底 + 点阵；语法高亮四色（蓝/绿/紫/橙）；等宽字体跑拉丁 + Noto 跑中文；路径栏 / 行号 / `// NOTE:` / `$` 命令行；细线卡片 + 主题色竖条 + 迷你数据图。

### 发布层（RPA）

`publish_flow.js` 在 Playwright MCP 环境执行，完整链路：

1. `file://` 导航读取当日 JSON（执行环境无 `require`，这是实测约束）
2. 打开发布页 → evaluate 点可见的「上传图文」tab（侧边栏同名隐藏元素会致 click 超时）
3. `setInputFiles` 注入 6 张图（封面优先）
4. 填标题 / 正文
5. 选「笔记含AI合成内容」声明（不选则发布按钮静默无响应）
6. 坐标点击红色「发布」按钮（封闭 shadow DOM 组件，DOM/a11y 均不可见）
7. 以 URL 含 `published=true` 判定成功

## 3. 关键设计决策

**Q：为什么数据与视觉解耦？**
A：视觉是高频迭代项（十轮用户反馈），数据是稳定项。解耦后换视觉不改数据、换数据不改视觉，模板可无限扩展。

**Q：为什么用 Pillow 而不是 HTML 渲染？**
A：零依赖、纯本地、像素级可控（渐变/柔光/颗粒/高光均可程序化），且避免了浏览器渲染的不确定性。代价是排版需自行处理换行与坐标——坑位已全部记录在 LESSONS.md。

**Q：发布为什么用坐标点击而非 DOM 操作？**
A：小红书创作平台的发布按钮是封闭 shadow DOM 自定义元素（`<xhs-publish-btn>`），外部无法查询内部结构；坐标点击是对此类「黑盒组件」最稳的交互方式，坐标通过截图像素扫描标定而非目视估算。

## 4. 异常与降级

| 失败点 | 策略 |
| --- | --- |
| 渲染报错 | 查 LESSONS.md 对应坑位（坐标/字体/图层三大类） |
| 发布超时/按钮无响应 | 不无限重试，保留产物 + 写草稿说明 + 通知人工 |
| 数据字段缺失 | 渲染器内置 fallback（cover_hook 缺失取首条 headline，title 缺失取 takeaways[0]） |
