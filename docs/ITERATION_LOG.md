# 视觉产品迭代记录（v1 → v10）

这个项目的视觉不是一次设计成的，而是**十轮「用户反馈 → 假设 → 参数化变更 → 验证」的迭代**。每轮反馈都被翻译成具体的视觉参数并沉淀为规范。这是数据驱动产品迭代的完整样本。

---

## v1–v2 · neo-brutalist → 赛博霓虹 HUD

- **反馈**：「像商务 PPT」「很丑，要贴合我小红书主页的深紫霓虹赛博夜城风」
- **动作**：从主页截图量化取色（深蓝 `#05071E` → 靛蓝 `#0B103C` → 暗紫 `#1C103E`），建立色彩基准；放弃主观平涂
- **沉淀**：账号视觉语言 = 深紫霓虹赛博夜城，成为后续所有版本的锚点

## v3–v4 · 色彩争议与色相环分布

- **反馈**：「不要这个粉色太难看，换！」（连续两次否定品红）
- **动作**：弃用品红/粉色；按色相环均匀分布四主题色（蓝/绿/紫/橙），保证四块各自独立可辨
- **沉淀**：用户审美底线清单（禁粉/品红、禁土黄褐、禁高饱和平涂）写入模板规范

## v5–v6 · 磨砂「一丢丢」的量化

- **反馈**：「有些偏商务，不过这样的深蓝我很喜欢」「不要磨砂玻璃，磨砂一丢丢就够了」
- **动作**：重写磨砂面板函数——去外发光、去顶边高光，投影 alpha 105→46、模糊 18→7、描边 2px/alpha120→1px/alpha64
- **沉淀**：「一丢丢磨砂」有了可执行数值定义；深蓝底保留为用户明确偏好

## v7–v8 · 信息层级与装饰做减法

- **反馈**：「底下那句话字体一样大，弱化他的信息层级」「下面那个框不要了，直接就是 70% 灰色字」
- **动作**：CTA 从「大标题+副标」改为单行同字号整句；删框删底色，70% 灰字（`#B0B0C0`）
- **沉淀**：装饰元素服务于信息层级，不做无意义视觉噪音

## v9 · 三段拆解与「发闷」根因

- **反馈**：「封面分三段，上面最满意，中间颜色有问题，最下面装饰有问题」
- **动作**：
  - 根因定位：四色块用半透明染色叠深底 → 发闷发灰；改**实色竖直渐变**（顶亮底深）+ 边缘亮色高光
  - 上段（页眉+主标题+副标+速览）冻结不动
  - 下段重排：灰字 → 蓝线 → 镜像页脚，与上段页眉同构
- **沉淀**：「用户最满意的部分立即冻结」成为迭代纪律

## v10 · 模板A定稿：目录 → 预告清单

- **反馈**：「参考前 top10 的小红书该类型爆款封面」「加的小字颜色要淡、字号要小」
- **动作**：
  - 中段从「板块名目录」升级为「爆款预告清单」：序号方块 + 板块名 + 条数 + **两行数字钩子**（新增 `cover_hook` 字段，`\n` 精确断行）
  - 小字参数化：条数 17px、钩子 27px，淡色值 `(210,216,238)`
  - CTA 灰字 70%→50%；蓝线改蓝→深蓝渐变、2px、左右边界与板块对齐
- **沉淀**：模板A 固化（模板A（`pipeline/render_template_a.py`）），「只换数据不动视觉」

## v11 · 模板B：面向程序员审美的第二套视觉

- **反馈**：「做 B 版本，简约、符合程序员审美、图文结合」
- **动作**：GitHub Dark 近黑底 + 语法高亮四色 + 等宽字体 + 路径栏/行号/`// NOTE:`/`$` 命令行；细线卡片 + 迷你数据图（图文结合）；总结页 CHANGELOG 风
- **验证**：数据层零改动，同一 JSON 直接渲染出风格迥异的成品——证明「数据-视觉解耦」架构成立
- **沉淀**：模板B 定为日常默认（模板B（`pipeline/render_template_b.py`）），A 归档备用

---

## 方法论沉淀

1. **反馈必须落到参数**：「淡一点」→ `alpha 46/blur 7`；「小一点」→ `27px/500`。拒绝模糊调整。
2. **冻结满意区**：用户明确满意的部分（如封面上段）立即设为不可变，后续迭代只动问题区。
3. **根因优先于现象**：「颜色发闷」的根因是半透明叠深底，不是色值本身——改渲染方式而非调色。
4. **架构验证靠副产品**：模板B 的顺利产出，反向证明了 v10 解耦决策的正确性。
